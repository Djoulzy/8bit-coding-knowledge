# Local cassette extraction

These files were extracted at the user's request without modifying the original
[TAP image](<../../../sources/Oric/L'Aigle d'Or/Aigle D'or, Le (1984)(Loriciels).tap>).
The `.tap` files are exact standalone cassette blocks, preserving their original
headers, names, load ranges and autorun bytes. The `.bin` files are byte-exact
payloads, without cassette headers. They contain
BASIC, machine code, assets and captured state together, not only executable
instructions. Both start at CPU `$0501`; load only one stage at a time.

| File | Load range, inclusive | Size | Purpose |
| --- | --- | ---: | --- |
| [aigledor.1.tap](aigledor.1.tap) | `$0501–$3F37` | 14,927 bytes | Standalone introduction tape block |
| [aigledor.2.tap](aigledor.2.tap) | `$0501–$9FFF` | 39,703 bytes | Standalone main-game tape block |
| [aigledor.1.bin](aigledor.1.bin) | `$0501–$3F37` | 14,903 bytes | Introduction / title / controls |
| [aigledor.2.bin](aigledor.2.bin) | `$0501–$9FFF` | 39,679 bytes | Main game and resident resources |
| [aigledor.1.basic.txt](aigledor.1.basic.txt) | BASIC records from B1 | Derived text | Token decoding, addresses and TAP offsets |
| [aigledor.2.basic.txt](aigledor.2.basic.txt) | BASIC records from B2 | Derived text | Token decoding, addresses and TAP offsets |
| [manifest.json](manifest.json) | Both blocks | JSON | Original TAP offsets, load addresses, payload and standalone-TAP hashes |

For the original two-stage loading sequence, use the original combined image.
When using the split images, the first stage still requests `AIGLEDOR.2`, so
provide the second tape block through the emulator/machine's tape interface.
Do not concatenate or simultaneously load the raw payloads into consecutive RAM:
both have the same starting address and the second replaces the first.

Recreate from the repository root:

```sh
python3 research/analyses/laigle-dor/tools/inspect_tape.py --extract research/analyses/laigle-dor/extracted
python3 research/analyses/laigle-dor/tools/verify_analysis.py
```

The BASIC text is an analytical reconstruction, not a runnable source export:
control bytes are escaped, address metadata is included, anomalous records are
preserved and the source assembler dialect is unknown. The tape blocks, binary
payloads and manifest are the authoritative extraction. Helpers generated by BASIC at `$0400/$0430`
are not separate original tape programs.

Original restrictions and attribution remain applicable; local extraction does
not grant redistribution rights. The current ignore rule covers
`research/sources/`; this extraction directory is visible to Git and has not been
staged or committed.
